# 推荐目标与评分（DamageAdvisor）

## 适用边界

只改"在若干可行打法里选哪一条"。单张牌的效果实现走 `card-semantics-change`。

## 1. 当前评分顺序（`SearchContext.IsBetter`）

```
不死（Lethal）                       ← 硬约束，永远第一
掉血 ≤ 预算（AdvisorSettings.HpLossBudget）  ← 超预算则退化为"掉血更少优先"
优先击杀（Kills）                     ← 跨回合：打死怪=省掉它下一轮攻击
最大伤害（Damage）                    ← 同预算内的最终比较
```

- 掉血预算由 `F7` 循环（0/1/2/3/5），持久化到 `DamageAdvisor.cfg`；0 = 严格保命。
- `Kills` 统计 `!Alive || DiesToPoison` 的敌人：中毒在**敌方行动前**结算，所以"毒杀"能阻止该怪出手。
- 来袭伤害 = 存活且不会被毒杀的敌人的 `Incoming`（`BaseIncoming - StrengthLoss×段数`，再乘虚弱 0.75）。

## 2. 评分必须处理的两类"看似平局"

- **平局要有资源判定**：伤害/击杀/掉血完全相同是常态（尤其手上有能力牌时）。必须补一条
  "完全平局时少花能量优先"（`EnergySpent` 更小者胜），否则 DFS 会先找到谁就用谁，
  出现"本回合没有收益的能力牌被白打"这类看起来像 bug 的推荐。
- **随状态变化的牌必须出牌时算**：`终结技`（按已打出攻击牌数）、`飞镖`（按手牌技能牌数）、
  `蜃景`（按当前敌人中毒）、`铭记死亡`（按本回合弃牌数）在 `Analyze` 阶段算死会得到常数，
  顺序优化就失效。统一用 `ScalingKind` 标记，在 `PlayCard` 里按当时的 `SearchState` 计算。

## 3. 改动时注意

- **不要为了"看起来更聪明"而破坏保命优先**：任何新指标都必须排在"不死"之后，并明确它相对于"掉血预算"的位置。
- 新指标的语义要能在面板/日志里解释清楚（例如"优先击杀"要在 `STATUS.md` 和 README 里写明理由）。
- 增加状态维度（如连续回合视野、牌组价值）时，先在 `SearchState` 里加字段并保证 `PlayCard` 正确推进，否则会出现"评分用了没被更新的值"这类隐蔽错误。

## 3. 回归清单（每次改评分都要过）

1. 能斩杀的场面是否给出斩杀线（日志里出现"✅ 击杀"）。
2. 预算 0 时，是否存在无伤解；无解时是否给出掉血最少的解。
3. 把预算调到 3，推荐是否愿意用血换输出（对比同一场面下的计划差异）。
4. 会毒杀的场面是否把该怪的来袭从计算里剔除。
5. 搜索规模（`nodes=`）是否仍然可控（同名卡去重后通常是几十~几千；顶到 `MaxNodes` 说明剪枝失效）。

## 4. 边界

不要引入需要外部数据（牌库统计、胜率表）的评分；本项目的立身之本是"只基于当前战斗状态、只算自己、只算这一回合"。
