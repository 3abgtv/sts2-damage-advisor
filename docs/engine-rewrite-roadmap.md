# engine/rewrite 路线图（新引擎）

> 面向后续会话的交接文档。分支 `engine/rewrite`，与 `master` 并行：`master` 继续收小修，新架构只在这条分支上长。
> 完整决策背景见 `STATUS.md` 顶部「engine/rewrite 分支进度」，本文件只讲**接下来怎么做**。

## 为什么做这件事

主模型（`DamageModel`）是"本回合快照"结构：每次面板刷新从 live 读一次值、跑一遍本回合搜索。
它**结构上做不到**跨回合推演与敌人 AI，遗物也永远只能靠逐张手写语义（300 个遗物，没有可读的变量表）。

参照 `Torch1230/CombatSolver`（687 文件 / 16.5 万行）的做法：**克隆 + 镜像引擎**。
关键结论（读源码得来，不是猜的）：

- 它**不执行 vanilla 逻辑**，而是逐个命令手写镜像（`CardCmd.Damage`/`PlayerCmd.GainEnergy`… 全自实现）
- 它**不省遗物的事**：遗物同样是逐条手写语义（覆盖率审计：508 条目，其中只有 82 条 EngineExact）
- 它**只支持单人**（AGENTS.md 硬约束），因为跨回合推演的前提"未来唯一"在多人下不成立

所以：新引擎买到的是**跨回合、敌人 AI、卡牌间交互、状态一致性纪律**，买不到"遗物省事"。

## 已完成（三阶段）

| 阶段 | 内容 | 状态 |
|---|---|---|
| 一 | 捕获 + 克隆（四项硬判据：捕获零影响 / 克隆体隔离 / RNG 不推进 / 开销 <1ms） | ✓ 实机 31+ 次 |
| 二 | 影子状态 + 命令镜像（伤害/格挡/能量/状态/抽牌/弃牌/奇巧/小刀/X 费/爆发 + 能力 8 张 + 特殊 5 张） | ✓ 逐步对齐 |
| 二 | 能力牌镜像实机确认（六项全等的差分通过） | ✓ |
| 三 | 与面板对接第一刀：**把主模型的推荐计划喂给新引擎重放，两边数字并排比对**（每回合自动跑） | ✓ |

**差分对照已抓出并修掉的两条真实规则差异**：

| 差异 | 证据 | 实质 |
|---|---|---|
| 融入暗影的格挡 ×2 | 预测 8 格挡 / 实机 14 | 游戏有、模型没有 |
| "每打出一张牌"类触发不给自己触发 | 打出余像时格挡仍 0 | 主模型对、新引擎写错 |

> 这两条都不是读文档读出来的，是**两边对数字对出来的** —— 这是整套方法唯一的价值来源。

## 接下来四步（按依赖顺序）

### 第 4 步：给新引擎加搜索（前提，必须最先）

**为什么必须先做**：现在它只会重放主模型的计划，不会自己找解；跨回合推演也需要"搜索"这个容器。

- 做法：在 `SimState` 上加 DFS/beam（可参照主模型的骨架：状态指纹去重 + 预算上限），
  但新引擎的状态更完整（有牌堆内容、敌方状态、能力），能支持更深/更准的搜索
- 验证：**新引擎自己的计划 vs 主模型的计划**并排比对（从"同一计划的数字对比"升级为"两个计划的优劣对比"）
- 规模：中等（几百行）

### 第 5 步：怪物 AI（跨回合的前提）

- 读 `MonsterModel.MoveStateMachine` 的下一状态（有 `FindNextMoveState`/`FollowUpState`）；
  `RandomBranchState` 带权重，要定策略（最坏情况 / 期望）
- ⚠️ **先决条件**：实机确认"读它不会消耗 RNG"。一旦读到就推进了 RNG，就违反"只读、不改 RNG"的底线
- 验证：读一次状态 → 连打几张牌 → 比对随机结果与"没读过"时是否一致
- 规模：小-中（API 已探明，主要工作量在随机分支的策略）

### 第 6 步：跨回合（做这套架构的真正目的）

- 补全 `EndTurn`：怪物按意图出手 + 中毒结算 + 回合推进（能量/抽牌/格挡/保留）
- 于是能做 **N 回合搜索** —— 主模型结构上做不到的事
- 验证：预测"两回合后敌人剩多少血 / 我掉多少"→ 照打两回合 → 六项全等
- 规模：中等（深度换性能，需要预算/剪枝/记忆化）

### 第 7 步：完整性（逐步，别一次做完）

| 项 | 说明 |
|---|---|
| 洗牌 | 弃牌堆洗回抽牌堆（现在只记账，抽牌堆空时不模拟） |
| **遗物** | 当初的动机之一。**只先做"影响本回合数值"的那批**，不要一次全做；注意遗物没有可读变量表，只能逐条写语义 + 分组验证 |
| 药水 | 同理 |
| 切换 | 新引擎接管面板推荐；多人自动降级到主模型（已定）→ 主模型退休或只做多人路径 |

## 两条贯穿始终的原则

1. **每一步都要能被差分验证** —— 加任何机制，都先想"我怎么在游戏里证明它对了"。
   管线的形态：新引擎给出预测 → 照做 → 面板自动核对（六项全等）。
2. **不动已发布的那条线** —— `master` 上只收小修与已攒的验证债；新架构成熟前不合并。

## 现在该做的第一件事

**先打几把，看面板那两行数字对不对得上**：

```
新引擎重放推荐：伤害 12 / 格挡 +10 / 掉血 3 / 剩 0 能量
　（主模型：伤害 12 / 格挡 +10 / 掉血 3）
```

因为两边的**机制覆盖已经对齐**（缺的"跨回合/怪物 AI"两边都缺），所以任何不一致都值得查。

收集到的差异本身就是路线图的路标：

- 差异集中在**机制**上（某个状态/某张牌算错）→ 先修镜像，别急着做搜索
- 机制都对、差异在**计划选得不好** → 这才轮到第 4 步（加搜索）

## 关键决策留档（已定，别重复讨论）

- **多人降级**：检测到 `state.Players.Count > 1` 时新引擎完全不介入（连快照都不捕获），继续用主模型
- **语义复用**：卡牌语义从现有 `SilentLogic` 迁移，不重写
- **卡牌语义表两处同步**：新引擎里 `SlyScore` / `ChooseDiscardIndex` 与主模型 `SlyValue` / `ChooseDiscard` 是同一公式的两份拷贝（注释里标了）——差分对比是防漂移的手段
- **测试牌**：F9 优先补齐"能力/格挡/状态/攻击"四类（`ProbeKit`），四类齐了才回到 `TestCards` 循环
